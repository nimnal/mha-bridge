> Неофициальный проект сообщества. Он не связан с Geely, ECARX или Home Assistant. Автор тестировал его на Geely Monjaro (Xingyue L). На других моделях на платформе ECARX поведение не проверялось.

---

## ✨ Главное

- 📡 **Локально, без облака.** Android-приложение работает на самом головном устройстве, читает данные через ECARX AdaptAPI и передаёт их в Home Assistant по WebSocket. Через сторонние серверы ничего не идёт.
- 🔌 **Двусторонняя связь.** Данные идут из машины в HA сразу при изменении (`local_push`, без опроса). Команды из HA (климат, подогрев, обдув) приходят в машину по той же подписке.
- 🧩 **Всё в одной установке.** Интеграция сама отдаёт файл карточки и регистрирует его как ресурс Lovelace. Отдельно ставить карточку не нужно.
- 🖱️ **Визуальный редактор:** карточки настраиваются в обычном окне Home Assistant (вкладки, переключатели, выбор цвета, список пресетов), YAML не обязателен; в окне выбора карточек у каждой есть живое превью.
- 🧊 **3D-вид сверху:** модель Monjaro, двери, окна, люк и багажник открываются на карточке вместе с машиной.
- 🪑 **Картинка по вкладкам:** на «Климате» фото салона сверху (без кузова) с подсветкой обогрева, обдува и потоков, цвет ткани и полосы выбирается.
- 🎨 **Векторная картинка Monjaro** для вида сбоку и сверху: цвет кузова, антихром по зонам, цвет колёсных арок.
- 📱 **Адаптивная вёрстка** от десктопа до узкого экрана смартфона.
- 🌐 **Русский и английский** интерфейс приложения, интеграции и карточек. Язык приложения выбирается автоматически по языку системы, его можно переключить вручную (карточка «Язык / Language» вверху).
- 🔐 **Токен HA хранится только на устройстве.** Для машины можно завести отдельного пользователя с долгосрочным токеном.

| Подогрев руля (выкл, 1–3) | `select` |

Окна, люк, массаж и подсветка описаны ниже в разделе «Окна, люк, замок и опции комплектации». Команд замков, багажника и капота пока нет.

### 🪟 Окна, люк, замок и опции комплектации

Эти функции есть не у всех машин, поэтому **сущности создаются только если автомобиль сам объявил функцию поддерживаемой** (приложение передаёт список в `meta.supported`; он запоминается и после перезапуска HA). Нет функции, значит нет сущности и нет блока в карточке. Исключение: люк и шторка есть на каждом Monjaro, поэтому их сущности создаются всегда (так же, как капот и багажник); лишнее скрывается в карточке вручную через `top_labels`.

| Что | Сущность | Примечание |
|---|---|---|
| Окна (4 шт.), люк, шторка панорамы | `cover` (положение 0–100 %) | Положения 0 / 25 / 50 / 75 / 100 %. Окно не держит положение меньше 10 %, шаг 4 %, как в штатном приложении |
| Наклон люка | `switch` | |
| Центральный замок | `binary_sensor` (device class `lock`) | Только чтение: `on` = не заперта |
| Задний климат: питание, AUTO, вентилятор (0–9), блокировка панели | `switch` / `select` | |
| Подогрев задних сидений (левое, правое; выкл, 1–3), задний обдув (лицо / ноги / оба) | `select` | необязательные |
| Температура задней зоны (одна общая, `number`) | `number` | необязательная |
| Очистка воздуха (G-clean) | `switch` | |
| Массаж водителя и пассажира: вкл, интенсивность 1–3, программа 1–8 | `switch` / `select` | **Опция комплектации.** На машине без массажа сущностей нет и блок в карточке не показывается |
| Атмосферная подсветка: вкл, яркость, режим, эффект, цвет (13 цветов) | `switch` / `number` / `select` | |

**Защита при открытии.** Закрывать окна, люк и шторку можно всегда. Открывать (и наклонять люк) приложение разрешает только если состояние центрального замка прочитано прямо сейчас и достоверно. Если замок не читается, команда открытия отклоняется, а в журнале приложения появляется причина. Это та же логика осторожности, что в штатном приложении автомобиля. В карточке можно дополнительно включить подтверждение: `confirm_open: true`.

**Скрыть блоки карточки** можно ключом `hide`: `windows` (окна и люк), `lock` (индикатор замка), `rear_climate`, `gclean`, `ambient`, `massage`. Массаж скрывается и сам, если сущностей нет. Ключ `massage` нужен, чтобы убрать блок там, где массаж есть, но не нужен.

**Багажник и капот.** Идентификаторы функций для них пока неизвестны. Кнопка **«Диагностика»** в приложении теперь выводит в журнал все константы AdaptAPI и значения функций, похожих на замки, багажник, капот, люк и окна (`=== КОНСТАНТЫ ADAPTAPI ===`). Скопируйте журнал и пришлите, и управление можно будет добавить следующим релизом.

### 🧊 3D-вид сверху

С ключом `view: top` (у `mha-card`, `mha-card-full` и `mha-card-panel`) вместо плоской картинки теперь рисуется **3D-модель Monjaro** (WebGL, three.js). Всё, что в машине открыто, открыто и на карточке:

| Состояние | Что видно |
|---|---|
| Дверь (4 датчика дверей) | дверь распахивается на петлях, кузов остаётся на месте и в том же размере, угол открытия (28°) подобран так, чтобы все четыре двери помещались в карточке |
| Капот и багажник | открываются по датчикам «Капот» и «Багажник», которые приложение создаёт само |
| Окна (`cover` каждого окна) | стекло уходит в дверь пропорционально положению 0–100 % |
| Подпись окна | под «Открыта/Закрыта» у каждой двери: «окно закр.», «окно 40%», «окно откр.» (янтарным, если не закрыто) |
| Подписи люка, шторки, капота, багажника | на самой модели: «Люк: Закрыт / 40% / Наклон / Проветр. / Открыт» («Проветр.» — люк лишь приподнят для проветривания, см. `sunroof_vent_max`) над передней половиной крыши и отдельно «Шторка: Закрыта / 40% / Открыта» над задней (стекло крыши разделено линией); «Капот» и «Багажник: Открыт / Закрыт» ; подписи показываются всегда; единое правило для всех значений карточки (двери, окна, люк, шторка, капот, багажник, шины, строки данных): если состояние неизвестно или не получено, вместо значения стоит «—», а не «Закрыта» или 0. «—» значит, что данных нет (проверьте сущности `binary_sensor.*_hood`, `binary_sensor.*_trunk`, `cover.*_sunshade` в Инструментах разработчика) |
| Люк | сдвигается назад по проценту открытия; режим «наклон» приподнимает задний край |
| Шторка панорамы | убирается назад по проценту |

Сохраняется всё прежнее: `car_color` красит кузов, `chrome_delete` затемняет хромовые детали, давление в шинах и состояние дверей подписаны у колёс, `rhd: true` зеркалит модель вместе с подписями. Если WebGL или файлы модели недоступны, карточка показывает прежнюю плоскую картинку. Отключить 3D можно ключом `car_3d: false`.

Модель (`car3d.bin`, ~1,3 МБ) и three.js (`three.module.min.js`, лицензия MIT) отдаёт интеграция, они подгружаются только когда на панели есть вид сверху. Арки колёс и антихром по зонам на 3D-виде не применяются (хром задаётся одним цветом).

```yaml
type: custom:mha-card
view: top
car_color: "#0b5159"
```

### 🪑 Картинка по вкладкам и салон

В карточках с вкладками (`mha-card`, `mha-card-panel`) картинка слева меняется вместе с вкладкой:

| Вкладка | Картинка |
|---|---|
| Обзор | вид сбоку (при `view: top` — вид сверху) |
| Климат | фото салона сверху в **исходных пропорциях**, без трансформации и без кузова, с мягким виньетированием по краям. На нём видно, что включено: подогрев и обдув каждого сиденья (три уровня, цвет и точки), подогрев руля (всё рисуется мягкими клубами «дыма»: тёплые крупные медленные у подогрева, мелкие быстрые холодные у обдува), подогрев **задних левого и правого** сидений (вентиляции у задних сидений нет, у центрального места ничего нет), **направление потока** спереди (струи идут из решёток торпедо, при «лицо» решётки подсвечиваются) и **задний обдув** (лицо из центрального тоннеля, ноги, лицо+ноги) (лицо, ноги, стекло) с цветом по заданной температуре (синий, нейтральный, оранжевый) и скоростью по вентилятору, обогрев лобового и заднего стекла |
| Кузов | вид сверху с крышей (3D, как раньше) |
| Комфорт | салон: подсветка по дверям и торпедо цветом и эффектом атмосферной подсветки, пульсация массажа на спинках |
| Данные | фото приборной панели: экраны светятся при включённом зажигании, снизу передача и скорость |

![Карточка: вкладки Климат, Комфорт, Данные](docs/gallery/tabs_phone.png)

![Панель на весь экран 1920×1080](docs/gallery/panel_climate.png)

**Цвет салона.** На фото ткань зелёная, а полоса под экраном бронзовая. В других комплектациях они серые и серебристые, поэтому цвета выбираются:

```yaml
cabin_fabric: green        # green (как на фото), light_gray, dark_gray или любой цвет: "#7a2a2a", "rgb(80,90,100)"
cabin_trim: silver         # bronze (как на фото), silver, gold или любой цвет
```

Перекраска идёт по маскам, блики и тени сохраняются; затрагиваются только ткань (сиденья, вставки дверей, полоса торпедо) и тонкие декоративные полосы (под экраном, на дверях).

**Флаги.**

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `tab_images` | `true` | `false`: одна картинка на все вкладки, как раньше. Или по вкладкам: `{ overview: side, climate: cabin, body: top, comfort: cabin, data: cockpit }`; значения `side`, `top`, `cabin`, `cockpit`, `none` |
| `cabin_fabric` | `green` | цвет ткани: `green`, `light_gray`, `dark_gray` или свой цвет; действует на всех вкладках, включая салон в 3D-виде сверху (через открытые двери и люк) |
| `cabin_trim` | `bronze` | цвет декоративной полосы: `bronze`, `silver`, `gold` или свой цвет |
| `cabin_effects` | всё включено | что рисовать поверх салона: `false` (ничего), список или карта из `heat`, `vent`, `wheel`, `air` (или `airflow`), `defrost`, `ambient`, `massage` |
| `cabin_opacity` | `0.6` | прозрачность эффектов подогрева, вентиляции и воздушных потоков на салоне: число `0…1` (или проценты `0…100`) для всех сразу, либо карта `{heat: 0.5, vent: 1, air: 0.7}` (`heat` — подогрев сидений, руля и стёкол, `vent` — вентиляция сидений, `air` — воздушные потоки). Подсветка и массаж не затрагиваются |

Салон всегда плоское фото и не зависит от WebGL и `car_3d`. Файлы `cabin.webp`, `cabin_mask.png`, `cockpit.webp`, `cockpit_mask.png` (около 0,4 МБ вместе) отдаёт интеgrация и подгружает только вкладки, которым они нужны.

## 🧠 Как это работает

```
 автомобиль ──► ECARX AdaptAPI ──► приложение MHA Bridge ──WebSocket──► Home Assistant
 (CAN, климат)   (на головном        (ru.mhabridge, служба       (интеграция mha_bridge,
                  устройстве)         переднего плана)            сущности и карточки)
```

1. Приложение запускается вместе с головным устройством (`BOOT_COMPLETED`) и работает как служба переднего плана.
2. Оно подключается к Home Assistant по адресу и долгосрочному токену, которые вы вводите в настройках.
3. Данные отправляются командой `mha_bridge/update`, а команды HA приходят по подписке `mha_bridge/subscribe`.
4. Команда `mha_bridge/info` нужна для проверки: «Проверить подключение» в приложении показывает, что HA доступен, токен принят и интеграция найдена.

## 📥 Установка

### Через HACS (рекомендуется)

1. В HA откройте **HACS → ⋮ → Custom repositories**.
2. Вставьте `https://github.com/nimnal/mha-bridge`, категория **Integration**.
3. Найдите **MHA Bridge** в HACS и нажмите **Download**.
4. **Перезапустите Home Assistant.**
5. **Настройки → Устройства и службы → Добавить интеграцию → MHA Bridge.** Введите имя автомобиля (по умолчанию «Geely Monjaro»).

Кнопка быстрой установки: [![Open your Home Assistant instance and open the repository inside HACS.](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=nimnal&repository=mha-bridge&category=integration)

### Вручную

1. Скопируйте папку `custom_components/mha_bridge` в каталог конфигурации HA: `config/custom_components/mha_bridge`.
2. Перезапустите Home Assistant и добавьте интеграцию, как в шаге 5 выше.

### Приложение на головном устройстве

1. Скачайте `MHA-Bridge.apk` из раздела [Releases](https://github.com/nimnal/mha-bridge/releases) и установите на головное устройство (разрешите установку из неизвестных источников).
2. В HA откройте свой профиль → **Безопасность → Долгосрочные токены доступа → Создать токен**. Лучше завести для автомобиля отдельного пользователя.
3. В приложении укажите адрес HA (например `http://192.168.1.10:8123`) и токен.
4. Нажмите **«Проверить подключение»**, затем **«Сохранить и запустить»**.

## 🔄 Обновление

Обновляйте интеграцию через HACS и **всегда перезапускайте HA**. После обновления нажмите Ctrl+F5 в браузере, иначе он может показать старый файл карточки или картинки. Приложение на головном устройстве обновляется установкой нового APK поверх. Для этого он должен быть подписан тем же ключом, что и предыдущий.

## 🖥️ Дашборды и карточки

Карточки подключаются сами. После перезапуска HA обновите страницу (Ctrl+F5), нажмите «Добавить карточку» и найдите «MHA Bridge»: у каждой карточки есть превью (если сущностей машины в HA ещё нет, она показывает встроенную демо-модель). Настроить карточку можно в визуальном редакторе или в YAML.

### 🖱️ Визуальный редактор

![Визуальный редактор](docs/gallery/editor.png)

«Изменить» у карточки открывает форму на штатных компонентах Home Assistant (светлая и тёмная темы по теме Home Assistant, а при теме «Авто» в профиле, то есть по теме системы; русский и английский по языку профиля). Пять вкладок: **Основное** (тип карточки, заголовок, трекер, масштаб, правый руль, проветривание люка, размер текста по каждому элементу), **Вид** (картинка и свои картинки, диски и их вращение, 3D, молдинги, антихром, вид сверху: датчики капота и багажника и подписи, цвета, салон: прозрачность и эффекты), **Действия** (тап по карточке и машине, окно по нажатию: какая карточка и есть ли карта, быстрые кнопки, скрытые блоки), **Пресеты** (список с добавлением, порядком и кнопкой «шесть стандартных»), **Данные и карта** (вкладки карточки, первая вкладка, запоминание вкладки и картинка каждой вкладки, навигация, вся карта: трекер, масштаб, пропорции, высота, тема, след, вкладка; топливо и шины). У пресета есть блок «Ещё шаги»: сиденья и окна по отдельности, задний климат, подсветка, любые действия HA. У каждого поля справа значок «?»: при наведении (или нажатии) всплывает подробное описание, что поле делает и что меняет. Все ключи YAML доступны в форме; единственное, что вводится YAML-блоком прямо в форме, — положение маркеров `car_image_hotspots` и список `actions` пресета. В конфиг попадают только изменённые ключи; режим YAML остаётся рядом.

| Тип | Что это |
|---|---|
| `custom:mha-card` | **С вкладками (основная).** Слева машина, запас хода и метки, справа вкладки «Обзор / Климат / Кузов / Комфорт / Данные». Подходит и для телефона, и для широких экранов, высота фиксирована. |
| `custom:mha-card-full` | **Длинная.** Всё одно под другим: машина, запас хода, пресеты, окна, климат, потоки воздуха, подогрев и вентиляция сидений, движение, шины, данные автомобиля, маршрут. |
| `custom:mha-card-compact` | **Компактная.** Запас хода, фото, чипы состояния и шесть кнопок климата. |
| `custom:mha-card-mini` | **Мини.** Заголовок, запас хода, три кнопки. Подходит для сетки 6×3. |
| `custom:mha-card-panel` | **Панель на весь экран.** Карточка с вкладками для ноутбука или настенного планшета: крупные цифры, картинка и кнопки, масштабируется под ширину и высоту экрана (рассчитана на 1920×1080). С включённой картой (`map: true`) делится на три колонки: машина, вкладки и кнопки по центру, карта в правой трети. Нужен экран не меньше 768×384 CSS-пикселей; на смартфоне в портрете и в узкой колонке она становится карточкой с вкладками (`rotate`, `panel_min_width`). Ставьте в вид «Панель (одна карточка)». Меньше минимума — ведёт себя как `mha-card`. |

Машину можно показать **сверху** вместо вида сбоку: ключ `view: top` у `mha-card`, `mha-card-full` и `mha-card-panel` (3D-модель с давлением у колёс и состоянием дверей). Своя картинка — `car_image` (сбоку) и `car_image_top` (сверху).

Минимальная карточка:

```yaml
type: custom:mha-card
```

Все остальные ключи необязательны.

### 🎨 Внешний вид автомобиля

```yaml
type: custom:mha-card
car_color: "#16181b"        # цвет кузова: любой CSS-цвет
wheels: type1               # диски на виде сбоку (оба сразу): type1 родные | type2 … type5
arch_color: black           # молдинги арок: black | original | body | любой цвет
chrome_delete:              # антихром на виде сбоку; true = все пять групп чёрным
  front_bumper: 1
  rear_bumper: 1
  doors: 1                  # нижний молдинг дверей
  rails: 1                  # рейлинги
  windows: 0.6              # молдинги стёкол
```

![Цвета арок](docs/gallery/arch_color.png)

- **`car_color`** перекрашивает только краску кузова. Стёкла, шины, диски, фары и все молдинги остаются как есть.
- **`chrome_delete`**: для каждой из пяти групп можно задать число 0…1 (степень затемнения, 1 = чёрный глянец), цвет (`"#202020"`, хром перекрашивается с сохранением бликов) или `body` (в цвет кузова). Молдинги всегда рисуются поверх краски.
- **`arch_color`**: `black` (по умолчанию), `original` (как на исходном фото, `car_color` не действует), `body` (цвет кузова) или любой цвет.
- **`wheels`**: дизайн дисков на виде сбоку, меняются оба колеса одним ключом. `type1` — родные (как на исходной картинке), `type2` … `type5` — другие диски Monjaro (см. `docs/gallery/wheels.png`). Работает вместе с `car_color`, `chrome_delete`, `arch_color` и `car_image_facing`.
- На виде сверху действуют `car_color` и (одним цветом) `chrome_delete`; цвет арок там не применяется.

### 🎚️ Пресеты (сценарии одной кнопкой)

Пресет — плитка под фото (в карточках с вкладками — на вкладке «Обзор»), которая одним нажатием выполняет список шагов: климат, окна, люк, шторка, подогревы и даже любые сервисы Home Assistant. Плитки выглядят так же, как кнопки климата, идут по три в ряд. **Всего не больше 8** (лишние отбрасываются). Шаги, для которых в машине нет сущности или нужной опции, пропускаются, поэтому один пресет работает на любой комплектации. Всё, что в пресете не указано, остаётся как есть.

**В коде нет встроенных пресетов.** Вся логика каждого пресета, включая привычные «Зима», «Лето», «Запотело», «Комфорт», «Проветрить» и «Всё выкл», записана в YAML карточки. Если пресета нет в списке `presets`, его нет и на карточке; если ключа `presets` нет совсем, плиток тоже нет. Готовые шесть пресетов лежат в файле [`examples/presets.yaml`](examples/presets.yaml): скопируйте их в конфиг и меняйте как угодно.

#### Как записать

**Список: точный набор и порядок плиток.** Каждый элемент это пресет с шагами; `name` и `icon` необязательны (по умолчанию подпись берётся из `id`, иконка `climate`).

```yaml
presets:
  - id: winter
    name: Зима                 # optional: the label on the tile
    icon: heat
    temp: 24
    auto: true
    ac: false
    defrost: true
    rear: true
    circ: outside
    seat_heat: "3"
    wheel: "3"
    seat_vent: "off"
  - id: summer
    name: Лето
    icon: cool
    temp: min
    auto: true
    ac: true
    defrost: false
    rear: false
    circ: inside
    flow: face
    seat_vent: "3"
    seat_heat: "off"
    wheel: "off"
  - id: defog
    name: Запотело
    icon: defrost
    temp: 24
    auto: false
    ac: true
    defrost: true
    rear: true
    circ: outside
    flow: window
    fan: "7"
  - id: comfort
    name: Комфорт
    icon: auto
    temp: 22
    auto: true
    ac: true
    defrost: false
    rear: false
    circ: auto
    seat_heat: "off"
    seat_vent: "off"
    wheel: "off"
  - id: vent
    name: Проветрить
    icon: fresh
    auto: false
    ac: false
    defrost: false
    rear: false
    circ: outside
    flow: face
    fan: "5"
  - id: "off"
    name: Всё выкл
    icon: climate
    auto: false
    ac: false
    defrost: false
    rear: false
    seat_heat: "off"
    seat_vent: "off"
    wheel: "off"
```

Можно писать и словарём: `id` пресета → его настройки (порядок как в конфиге). Пресет без шагов (только `name` / `icon`) не показывается, `enabled: false` скрывает пресет, не удаляя его. `presets: true` больше ничего не включает, а `presets: false` просто скрывает блок.

```yaml
presets:
  parking:
    name: Парковка
    icon: mdi:car-brake-parking
    windows: closed             # все четыре окна
    sunroof: closed
    sunshade: closed
    ac: false
    auto: false
  dog:                          # «собака в машине»
    name: Собака
    icon: mdi:dog
    windows: 30                 # окна на 30 %
    temp: 20
    fan: "3"
    ac: true
```

#### Общие ключи пресета

| Ключ | Что делает |
|---|---|
| `name` | Подпись на плитке (по умолчанию — `id`) |
| `icon` | Иконка: встроенная (`heat`, `cool`, `defrost`, `auto`, `climate`, `fresh`, `steering`, `seatheat`, `seatvent`, `lock` …) **или любая Material Design Icon: `mdi:название`** — каталог на https://pictogrammers.com/library/mdi/ |
| `id` | Служебное имя (в списке); в словаре — это ключ |
| `enabled` | `false` — скрыть пресет, не удаляя его из конфига |

#### Климат

| Ключ | Значения | Что делает |
|---|---|---|
| `temp` | число, `[водитель, пассажир]`, `min`, `max` | Температура обеих зон |
| `temp_driver`, `temp_passenger` | число, `min`, `max` | Температура одной зоны (приоритетнее `temp`) |
| `rear_temp` | число | Температура задней зоны |
| `fan` | `"1"`…`"9"` | Скорость вентилятора (в кавычках) |
| `flow` | `face`, `leg`, `face_leg`, `window`, `face_window`, `leg_window`, `all`, `auto` | Направление потока |
| `auto`, `ac` | `true` / `false` | Авто-режим, кондиционер |
| `defrost`, `rear` | `true` / `false` | Обогрев лобового, заднего стекла |
| `circ` | `inside`, `outside`, `auto` | Рециркуляция |
| `seat_heat`, `seat_vent` | `off`, `"1"`, `"2"`, `"3"` | Подогрев / вентиляция передних сидений (подогрев — и задних) |
| `seat_heat_driver`, `seat_heat_passenger`, `seat_heat_rear_left`, `seat_heat_rear_right`, `seat_vent_driver`, `seat_vent_passenger` | то же | Одно сиденье (приоритетнее общего) |
| `wheel` | `off`, `"1"`…`"3"` | Обогрев руля |
| `rear_climate`, `g_clean` | `true` / `false` | Задний климат, очистка воздуха |
| `rear_flow` | как у передних | Направление заднего потока (вентилятор общий на весь салон) |
| `ambient` | `true` / `false` | Подсветка салона |
| `ambient_brightness` | число | Яркость подсветки |

#### Окна, люк, шторка

| Ключ | Значения | Что делает |
|---|---|---|
| `windows` | `closed`, `open`, `0`…`100` | Все четыре окна сразу (`closed` = 0, `open` = 100 %) |
| `window_driver`, `window_passenger`, `window_rear_left`, `window_rear_right` | то же | Одно окно (приоритетнее `windows`) |
| `sunroof` | `closed`, `open`, `0`…`100`, `vent` | Люк; `vent` — приоткрыть для проветривания (наклон), `closed` ещё и выключает наклон |
| `sunshade` | `closed`, `open`, `0`…`100` | Шторка |

Окна и люк управляются, только если машина отдаёт их сущности (см. раздел «Окна, люк…»). Подтверждение `confirm_open` для пресетов не спрашивается: вы сами написали, что они должны делать.

#### Любые сервисы Home Assistant — `actions`

Пресет может вызвать что угодно: включить свет, запустить скрипт, отправить уведомление. Формат такой же, как в автоматизациях:

```yaml
presets:
  leave:
    name: Ухожу
    icon: mdi:exit-run
    windows: closed
    sunroof: closed
    ac: false
    actions:
      - action: light.turn_off
        target: { entity_id: light.garage }
      - action: script.turn_on
        target: { entity_id: script.lock_house }
      - action: notify.mobile_app_phone
        data: { message: "Машина закрыта" }
```

Шаги выполняются по порядку с паузой около 0,3 с: сначала климат, потом окна и люк, затем `actions`. Пока идёт пресет, плитки на пару секунд блокируются от повторных нажатий. Плитки пресетов не подсвечиваются и не запоминают состояние: это разовое действие (как «тактовая» кнопка), которое выполняет сценарий.

### ⛽ Топливо

Полоса запаса хода меняет цвет по трём ступеням:

| Уровень | Цвет | Метка |
|---|---|---|
| выше `fuel_warn` (25 %) | зелёный `--geely-accent` | нет |
| от `fuel_warn` до `fuel_critical` | жёлтый `--geely-warn` | «Мало топлива» |
| ниже `fuel_critical` (10 %) | красный `--geely-critical` | «Топливо на исходе» |

Процент считается от `tank_size` (по умолчанию 60 л). Цвета можно задать ключами `fuel_color_ok`, `fuel_color_warn`, `fuel_color_critical` или переменными темы HA.

### 🛞 Шины

Если давление в любой шине ниже `tire_critical`, оно красное: в полной карточке, на виде сверху, в compact (красная метка) и в mini (красная строка под запасом хода). Значение задаётся в единицах датчика (обычно бар), цвет — `tire_color_critical`.

### 🗺️ Навигация

Кнопки «Проложить маршрут к машине» создаются по списку `nav`, порядок сохраняется:

| Ключ | Приложение |
|---|---|
| `yandex` | Яндекс Карты |
| `maps` | Google Карты |
| `osm` | OpenStreetMap |
| `apple` | Apple Карты |
| `here` | HERE WeGo |

`nav_mode: route` строит маршрут к машине, `locate` просто показывает, где она. Способ `nav_travel`: `driving`, `walking`, `transit`, `bicycling` (в OSM `transit` заменяется автомобилем).

### 👆 Клик по значениям

Нажатие на скорость, обороты, передачу, зажигание, двигатель, давление в шинах (и все подписи на виде сверху: двери, окна, люк, шторка, капот, багажник), пробег, топливо, запас хода, температуры и ремни открывает штатное окно HA с историей. Отключается ключом `more_info: false`.

Тап по самой карточке и по картинке машины настраивается ключами `tap_action` и `car_tap_action`: `expand` (полная карточка в окне, по умолчанию у компактной), `none`, `navigate` (например, на страницу с панелью), `url` (путь внутри HA вида `/car` открывается в самом приложении, полный адрес — во внешнем браузере), `more-info`, `perform-action`. Это же есть во вкладке «Действия» редактора.

### 📚 Все ключи конфигурации

| Ключ | По умолчанию | Описание |
|---|---|---|
| `view` | `side` | `mha-card`, `mha-card-full`, `mha-card-panel`: `side` — машина сбоку, `top` — сверху (3D) |
| `tabs` | все пять | Только `mha-card` и `mha-card-panel`: какие вкладки и в каком порядке (`overview, climate, body, comfort, data`). Вкладка «Комфорт» исчезает сама, если нет подсветки и массажа |
| `default_tab` | `overview` | Только `mha-card` и `mha-card-panel`: вкладка при открытии; карточка всегда открывается на ней |
| `remember_tab` | `false` | Только `mha-card` и `mha-card-panel`: `true` — помнить последнюю выбранную вкладку в браузере вместо `default_tab` |
| `height` | `440` | Только `mha-card` и `mha-card-panel`, на широком экране: высота области вкладки в пикселях, `0` = без ограничения |
| `tab_images` | `true` | Только `mha-card` и `mha-card-panel`: картинка меняется с вкладкой (`false` отключает; можно задать по вкладкам: `side`, `top`, `cabin`, `cockpit`, `none`) |
| `map` | выключена | Карта внутри карточки (штатная карта Home Assistant в стиле карточки, с масштабом и прокруткой). `true` или `{ entity, zoom, aspect_ratio, theme_mode, hours_to_show, height, tab }`: `entity` — трекер (по умолчанию `tracker`), `zoom` — масштаб по умолчанию (`15`), `aspect_ratio` (`16:10`), `theme_mode` (`auto`/`light`/`dark`), `hours_to_show` — след пути, `height` — высота в px вместо пропорции, `tab` — на какой вкладке (`overview`). Ещё: `title`, `center` (`follow`/`fixed`), `locate_button`, `marker` (`car` по умолчанию, `default` — штатный, или адрес картинки), `marker_size`, `marker_rotate`, `caption`, `label`, `label_attribute`, `label_unit`, `address_entity`, `marker_heading`, `entities`, `geo_location_sources`, `auto_fit`, `fit_zones`, `trail_color`, `trail_width`: подробно в docs/CUSTOMIZATION.md. Работает в `mha-card`, `mha-card-full`, `mha-card-panel` |
| `stable_tabs` | `true` | Только `mha-card` и `mha-card-panel`: картинка лежит в «сцене» одной формы, и кнопки не прыгают при смене вкладок. `false` — высота картинки своя на каждой вкладке (карточка компактнее) |
| `headlights` | `true` | Пока двигатель работает (`engine_running`), передние и задние фары светятся на виде сбоку и сверху (в 3D тоже). `false` — выключить |
| `accent` | `green` | Основной цвет карточки (по умолчанию зелёный): имя (`blue`, `orange`, `violet`, `pink`, `red`, `cyan`, `amber`, `lime` и др.) или любой CSS-цвет, например `"#ff8a3d"` |
| `warn_color`, `critical_color` | янтарный, красный | Цвет предупреждений и цвет критичных значений (давление шин и т.п.) |
| `text_size` | не задан | Размер текста: число (множитель до 4, например `1.15`, или размер в px), либо словарь по типам элементов: `all`, `title`, `status`, `big`, `side`, `unit`, `heading`, `button`, `chip`, `tab`, `row`, `stepper`, `window`, `tire`, `caption`, `label3d`. Подробнее: [docs/CUSTOMIZATION.md](docs/CUSTOMIZATION.md#10-цвет-темы-и-размер-текста) |
| `zoom` | `1` | Общий масштаб любой карточки, от `0.5` до `2` (например `0.85` — на 15 % мельче). У `panel` подстраивает автоматический подбор: если справа появилась полоса прокрутки, поставьте `zoom: 0.85` или меньше |
| `scale` | авто | Только `panel`: абсолютный масштаб (например `1.6`, можно и меньше единицы, от `0.5`). По умолчанию подбирается по размеру окна |
| `panel_height` | остаток окна | Только `panel`: высота карточки в пикселях |
| `panel_min_width` | — | Только `panel`: если ширина карточки в px меньше этого числа (например `900`), панель показывается как карточка с вкладками (портретная раскладка). Без ключа — только когда не хватает места для колонок |

### 🧱 Библиотека машин

Встроенная машина задаётся ключом: `car_image: monjaro`. Для ключей из библиотеки направление `car_image_facing` зеркалит и картинку, и маркеры. Для своего файла (`car_image: /local/my-car.png`) направление и маркеры задаются вручную.

## 💡 Примеры автоматизаций

Названия сущностей зависят от имени автомобиля в настройках. Примеры даны для «Geely Monjaro».

**Прогрев салона перед выездом:**

```yaml
automation:
  - alias: "Прогрев Monjaro по будням"
    trigger:
      - platform: time
        at: "07:30:00"
    condition:
      - condition: time
        weekday: [mon, tue, wed, thu, fri]
    action:
      - service: switch.turn_on
        target: { entity_id: switch.geely_monjaro_climate_auto }
      - service: number.set_value
        target: { entity_id: number.geely_monjaro_driver_temperature }
        data: { value: 22 }
      - service: select.select_option
        target: { entity_id: select.geely_monjaro_driver_seat_heating }
        data: { option: "2" }
```

**Дверь осталась открытой:**

```yaml
automation:
  - alias: "Monjaro: дверь открыта"
    trigger:
      - platform: state
        entity_id:
          - binary_sensor.geely_monjaro_driver_door
          - binary_sensor.geely_monjaro_front_passenger_door
          - binary_sensor.geely_monjaro_rear_left_door
          - binary_sensor.geely_monjaro_rear_right_door
        to: "on"
        for: "00:05:00"
    action:
      - service: notify.notify
        data: { message: "Дверь автомобиля открыта уже 5 минут" }
```

**Упало давление в шине:**

```yaml
automation:
  - alias: "Monjaro: низкое давление в шинах"
    trigger:
      - platform: numeric_state
        entity_id:
          - sensor.geely_monjaro_tire_front_left
          - sensor.geely_monjaro_tire_front_right
          - sensor.geely_monjaro_tire_rear_left
          - sensor.geely_monjaro_tire_rear_right
        below: 1.8
    action:
      - service: notify.notify
        data: { message: "Низкое давление в шине: {{ trigger.to_state.name }} — {{ trigger.to_state.state }} бар" }
```

**Мало топлива:**

```yaml
automation:
  - alias: "Monjaro: мало топлива"
    trigger:
      - platform: numeric_state
        entity_id: sensor.geely_monjaro_fuel_level
        below: 8
    action:
      - service: notify.notify
        data: { message: "В баке меньше 8 литров" }
```

## ⚠️ Известные ограничения

- Работает только пока включено головное устройство и запущено приложение. При выключенной машине сущности становятся недоступными.
- Набор функций зависит от прошивки и комплектации. Состояние замка читается, но команд замка, багажника и капота пока нет: их идентификаторы неизвестны (см. «Диагностика»).
- Окна, люк, шторка, задний климат, массаж и подсветка проверены только по исходникам штатного приложения и в тестовом HA, на живой машине их ещё не пробовали.
- 3D-вид сверху не поддерживает цвет арок и антихром по зонам (хром задаётся одним цветом).
- Белый цвет кузова получается слегка кремовым: перекраска сохраняет светотени исходной серой машины.
- Для узнаваемой картинки другой модели нужно подготовить свои картинки и маркеры (`car_image`, `car_image_hotspots`).
- Проверено на Geely Monjaro, на других автомобилях ECARX поведение не гарантируется.
